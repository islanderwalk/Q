第 3 題・第 2 小題｜架構圖

PTT 八卦板全文搜尋 ETL（GCP + Python）

依實測規模設計：每天約 890 篇新文章｜7 天約 6,200 篇、23 萬則留言、23 MB 純文字｜每天約 6,300 次請求（0.073 次/秒）

外部來源

PTT 網頁版

www.ptt.cc／八卦板

  • 沒有 API，只能抓網頁
  • 過量請求會被擋
  • 需帶 over18 cookie
排程

Cloud Scheduler：每小時觸發一次

ETL 主體（Extract → Transform → Load）

Cloud Run Job「crawl」

Python｜單一 worker 依序抓｜每秒 1 次｜每小時跑約 5–8 分鐘

規格 1 ① discover：找新文章並首抓

從上次的頁碼重讀到最新頁（跳過置底公告），新文章各抓一次 → 發文後 1 小時內入庫

≈ 960 次/天
規格 2 ② refresh：重抓 7 天內的文章

挑「發文 7 天內、且 23 小時以上沒抓過」的文章重抓留言 → 每篇每天更新一次

≈ 5,340 次/天
③ 共用：抓取 → 解析 → 寫入

解析內文、留言、刪文佔位；失敗退避重試；狀態全存在 BigQuery，失敗下一輪自動補

原始資料

Cloud Storage：原始 HTML

gzip 壓縮、保留 30 天；7 天份約 105 MB
解析規則改了可以直接重新解析，不必重爬 PTT

整理後的資料（依發文日分區）

BigQuery

  • articles：文章 ID、標題、作者、發文時間、內文、上次抓取時間（約 6,200 列）
  • comments：文章 ID、序號、推/噓/→、帳號、內容、時間（約 23 萬列）
  • index_slots：頁碼、格位、文章 ID（給不變量檢查用）
純文字約 23 MB 爬蟲狀態也存這裡 → job 可重跑不重複
查詢服務

Cloud Run Service「search」（FastAPI）

子字串比對、不需斷詞；只掃最近 7 天分區；每次查詢約 1–3 秒

使用者

輸入關鍵字 → 7 天內的文章與留言

資料品質（第 4 小題）

Cloud Run Job「verify」：每天一次

  • 每個填滿的列表頁剛好 20 格，且文章 ID 的時間由舊到新
  • 每個非刪文的格子都有對應的文章；留言只增不改（前綴不變）
  • 列表推文數 ≈ 推 − 噓（容許 ±2）
