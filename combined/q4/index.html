網頁怎麼拿到貼文：HTML → JS → GraphQL

依 2026-11-15、11-16 實抓 threads.com/@zuck
  1. HTML：伺服器最先回的文件打開網址時伺服器先回這份（zuck 約 1.1 MB），就是「檢視網頁原始碼」看到的東西。裡面有頁面骨架，還有用 <script type="application/json"> 裝的資料包：它不是程式，瀏覽器不執行，只是借標籤裝資料。未登入時最新 4 串就在這裡（下方實拍的紅框）。
  2. JS：放進 HTML 的兩種寫法一種直接寫在 <script>…</script> 裡，一種只寫 <script src="網址"> 讓瀏覽器另外下載。Threads 的 HTML 裡 src 全是 data: 開頭的小載入器；真正的程式拆成幾百個 .js 檔放在 static.cdninstagram.com，網址列在 HTML 的清單（rsrcMap 等）裡，由載入器去下載。
  3. GraphQL：往下捲再補JS 跑起來先把那 4 串畫出來；往下捲，JS 就送 POST /graphql/query 拿下一批（下方實拍的藍框）。爬蟲跳過前兩步、直接送這個請求，1 次拿最新 10 串，所以不必抓 HTML。

doc_id 是什麼，為什麼說「可從網頁 JS 取得」

  • 一般的 GraphQL 請求要把整段查詢語句（查誰、要哪些欄位）放進請求。Meta 改成把查詢語句先存在伺服器、每段給一個編號，網頁只送編號，這個編號就是 doc_id。抓個人頁貼文這段，11-15 的編號是 29427891256864466。
  • 編號不在 HTML 裡，寫死在某個 .js 檔：__d("BarcelonaProfileThreadsTabRefetchableDirectQuery_threadsRelayOperation", …a.exports="29427891256864466"…)。11-15 從 HTML 解出 663 個 JS 網址全部下載，其中 1 個檔案有這行；用無頭瀏覽器開同一頁對照，網頁自己用的也是這個值。
  • 編號會換：10-29 抓到的 39551525044493602，11-15 已回 execution error。所以不能寫死；回應裡沒有 data.mediaData 就重跑「抓 HTML → 下載 JS → 搜查詢名 → 取新編號」，純 HTTP 就做得到，不必開瀏覽器。
  • 只換編號不夠，還要一起帶 52 個 __relay_internal__pv__* 開關參數，值從 HTML 裡取得。

封鎖與代理選擇

單一 IP 壓測重播（2026-10-29，個人網路 IP，5 req/s）

200 有貼文401（回應 119 bytes）第 102 次 · 成功 82 · 401 20
+5 秒GraphQL 401；HTML 200 有貼文
+60 秒GraphQL 401；換新 token 也 401；HTML 200
+300 秒GraphQL 401；HTML 200

結論：封鎖以 IP 為單位、只擋匿名 GraphQL、超過 5 分鐘未解。10-28 打第 2 頁時衝到 10.7 req/s 共 560 次都沒被擋，和這次矛盾；請求類型與出口 IP 都不同，分不出是哪個造成的。單 IP 可長期撐住的速率與解封時間都還沒測到。

防封做法

  • 住宅輪替代理，每個請求換 IP
  • 收到 401 就把該 IP 剔除，退避後再試
  • 監控成功率與每次回傳的串數，異常就降速
  • token 由無頭瀏覽器定期更新，跨帳號共用
  • doc_id 會換，從網頁 JS 取得（11-15 已驗證：HTML → JS bundle → doc_id，另帶 HTML 裡的旗標值）

為什麼不用 ISP 固定 IP 當主力

需要幾個 IP，取決於單 IP 能長期撐住的速率，這個沒測到。再加上一旦被封，至少 5 分鐘不會解，固定 IP 池很快就會耗盡。

雲端 IP：從 GitHub Actions（Azure）打過 1 次是 200、有 10 篇；只有一次，看不出雲端 IP 段會不會直接被封。

robots.txt

2026-10-30 抓取 · 8,506 bytes
User-agent: *
Disallow: /

對所有爬蟲整站禁止，並註明未經 Threads 書面許可不得以自動化方式蒐集資料。GPTBot 等 14 組點名的爬蟲也是整站禁止；Googlebot 等 22 組只擋部分路徑。

robots.txt 是君子協定，沒有技術上的強制力；它的作用是留下「網站已明示拒絕」的紀錄。答案 (b) 最後一句就是在講這個法遵風險。
